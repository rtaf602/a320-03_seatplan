# คู่มือออกแบบ Galley / ห้องน้ำ / ประตู — สำหรับนำไปประยุกต์กับเครื่องลำอื่น

เอกสารนี้อธิบายว่า A320-03 (ยกแบบมาจาก A320-05) เพิ่ม Galley, ห้องน้ำ (LAV) และประตูเข้าไปในระบบ Seat Plan อย่างไร
(ต่อยอดจากแบบของ A340 แต่จัดผังตามคู่มือ A320 CCOM-S 02-140) เพื่อให้โปรเจกต์อื่นศึกษาและทำตามได้

---

## 1. ภาพรวมระบบ (4 ส่วนต้องตรงกัน)

| ส่วน | ไฟล์ | ใช้ทำอะไร |
|---|---|---|
| ผังบนเว็บ | `index.html` (`ZONES`, `GLAYOUT`, `LAVS`, `EQ_CABIN`) | หน้ากรอกข้อมูล, PREVIEW, PDF ทั้งสองแบบ |
| ผังในชีท | `layout.js` (`seatPlanLayout` + `planSheet`) | แท็บ "ผังที่นั่ง" ใน Google Sheet และใน EXPORT TO EXCEL |
| Excel | `export-excel.js` | 5 แผ่นงาน รวม "Galley และห้องน้ำ" |
| Apps Script | `apps-script/server.js` (+ `layout.js` → `Code.gs`) | อ่าน/บันทึกค่า, ประวัติ, สร้างแท็บ |

**รหัสรายการ (id) ต้องเหมือนกันทุกส่วน** — เว็บส่ง `{id, s, note}` ไป Apps Script และ Apps Script หาช่องในชีทจาก id → ชื่อ
- อุปกรณ์ Galley: `<GALLEY>-<CODE>` เช่น `FWD-OVEN-1`, `AFT-STOWAGE-9`, `AFT-HEATER-1`
- ห้องน้ำ: `LAV-<KEY>` เช่น `LAV-A`, `LAV-FV`, `LAV-CV`, `LAV-D`, `LAV-E`
- ชนิด (`kind`): `seat`, `mon`, `eq` (อุปกรณ์ Galley), `lav` (ห้องน้ำ)

สภาพ: ที่นั่ง `SEAT_S`, Monitor `SEAT_M`, Galley/ห้องน้ำ `SEAT_E = ['ใช้งานได้','ใช้งานได้บางส่วน','ใช้งานไม่ได้']`
(Galley/ห้องน้ำเก็บในช่อง `s` เหมือนที่นั่ง)

## 2. หน้าเว็บ (`index.html`)

### 2.1 ข้อมูล Galley — `GLAYOUT`
แต่ละ Galley วาดเป็นตาราง (CSS grid) ตามภาพคู่มือ "มองจากหน้า Galley ซ้ายไปขวา"

```js
FWD:{cols:7, nrows:6, pw:205,               // pw = ความกว้างบนหน้า 3 ของ SUMMARY (px)
  bands:[ {r0:1,r1:3,h:46,w:[1,1,.9,.9,.9,.9,.8]},   // เหนือเคาน์เตอร์: แถว 1-3, สัดส่วนคอลัมน์
          {r0:4,r1:6,w:[1,1,1.8,1.8,1]} ],            // ใต้เคาน์เตอร์: แถว 4-6 มีคอลัมน์ของตัวเอง
  cells:[
    {id:'STOWAGE-1', type:'STOWAGE', label:'Stowage 1', b:'Stow 1', c:1, r:1, v:1},
    {n:'Elec. Panel', c:3, r:1, cs:2},          // ไม่มี id = ช่องลายเส้น ไม่ได้ตรวจ
    {id:'FRIDGE-1', type:'FRIDGE', label:'Refrigerator', b:'Refrigerator', c:1, r:2, rs:2, v:1},
    ...
]}
```
| ฟิลด์ | ความหมาย |
|---|---|
| `id` / `type` | รหัสและชนิด (ชนิดใช้ในตารางสรุป, ชื่อเต็มอยู่ใน `TYPES`) |
| `label` | ชื่อเต็ม (หัวหน้าต่างตอนแตะ, รายการ, Excel) |
| `b` | ข้อความสั้นบนปุ่ม · `sub` = บรรทัดเล็กใต้ชื่อ |
| `c`,`r`,`cs`,`rs` | คอลัมน์/แถวเริ่ม และจำนวนช่องที่กิน (แถวนับต่อเนื่องทั้ง Galley; คอลัมน์นับภายใน band) |
| `v:1` | ชื่อแนวตั้ง (ช่องแคบสูง) — ทำด้วย `transform: rotate(-90deg)` ไม่ใช้ `writing-mode` เพราะตัวสร้าง PDF (html2canvas) วาด `writing-mode` กลับด้าน |
| `bands` | แบ่ง Galley เป็นช่วงที่มีสัดส่วนคอลัมน์ต่างกัน (วัดจากภาพคู่มือ) ทำให้ไม่ต้องใช้คอลัมน์ร่วมกันทั้งตู้ |

**กติกาที่ตกลงกับผู้ใช้**
- ไล่เลข Stowage จาก **แถวบนลงล่าง ซ้ายไปขวา** (และเลขในชนิดอื่นแบบเดียวกัน)
- ของที่อยู่ในช่องเดียวกันแต่เสียแยกกันได้ ให้แยกเป็น 2 รายการ เช่น Stow 4 / Water Heater, Stow 9 / Water Heater
- ช่องที่ไม่ได้ตรวจ (Elec. Panel, Sink, ขอบลำ) แสดงเป็นลายเส้นพร้อมชื่อ เพื่อให้รูปร่างตรงคู่มือ
- 220VAC Power Outlet ใช้ไอคอนปลั๊ก + "220V" เหมือนกันทุก Galley ทุกหน้าจอ

### 2.2 ห้องน้ำ — `LAVS`
```js
var LAVS={A:{name:'LAVATORY A',short:'LAV A',zone:'F'}, FV:{...,zone:'A'}, CV:{...,zone:'C'}, D:{...}, E:{...}};
```
`zone` = นับในสรุปห้องน้ำของโซนไหน · ความกว้างบนผัง = จำนวนที่นั่งฝั่งนั้นในโซนนั้น
(`{lav:'FV', seats:2}` = กว้าง 2 ที่นั่ง, ไม่ระบุ = เต็มฝั่ง 3 ที่นั่ง, `room:1` = กว้างเท่าห้อง Commander Center)

### 2.3 วางในผัง — `ZONES[].lines`
นอกจากแถวที่นั่ง/Monitor แล้ว มีบรรทัดชนิดใหม่:
```js
{fac:{L:[{lav:'A',room:1}], R:[{gal:'FWD'}]}}        // ซ้าย | ทางเดิน | ขวา ใช้รางเดียวกับที่นั่ง
{fac:{C:[{gal:'AFT'}]}}                              // เต็มความกว้างลำ
{door:{code:'1',  kind:'door'}}                      // แถบประตู เต็มความกว้าง
{door:{code:'FWD',kind:'exit'}}                      // ทางออกฉุกเฉิน: แสดงเฉพาะขอบซ้าย/ขวา ไม่พาดผ่านที่นั่ง
{door:{code:'AFT',kind:'exit'}, fac:{R:[{lav:'CV',seats:2}]}}   // ทางออกแถวเดียวกับห้องน้ำ
```
แถว Galley/ห้องน้ำใช้ `.row` / `.side` / `.aisle` ชุดเดียวกับที่นั่ง จึงตรงแนวที่นั่งเสมอ (เช่น FWD GALLEY = แนว 1D-1F)

### 2.4 หน้า 3 ของ SUMMARY — `EQ_CABIN`
ลำตัวเครื่องแนวนอน หัวซ้าย-ท้ายขวา, บน = ฝั่งขวา (D-F), ล่าง = ฝั่งซ้าย (A-C), เส้นประกลาง = ทางเดิน (AISLE)
แต่ละ segment: `{z:'ป้ายโซน', R:[...], L:[...], X:[...]}` หรือ `{seat:'ชื่อบล็อก', sub:'...'}` หรือ `{door:{...}}`
ห้องน้ำวาดเป็นกล่องแนวตั้ง สูงตามสัดส่วนเดียวกับหน้ากรอก (3 ที่นั่ง = เต็มฝั่ง, 2 ที่นั่ง ≈ 80%)

### 2.5 PDF (สิ่งที่เรียนรู้จาก html2canvas)
- **600 dpi**: `pdfScale()` คำนวณ scale จากความกว้างบนกระดาษ จำกัดตามขนาด canvas สูงสุดของ iOS/Android และสร้างทีละหน้าเพื่อไม่ให้หน่วยความจำเต็ม
- **ไม่ตัดข้ามหน้า**: รายงาน ALL PAGES แบ่งเป็น `.blk` ทีละตาราง/โซน; ถ้าก้อนยาวเกินหน้าจะตัดที่ขอบแถวเท่านั้น
- **ลายเส้น**: ใช้ SVG data-URI แทน `repeating-linear-gradient` (html2canvas วาด gradient ซ้ำผิดเป็นสีทึบ)
- **ไอคอน SVG**: ใส่ `width`, `height`, `fill` ในแท็ก SVG เอง (html2canvas ไม่อ่าน CSS ภายใน SVG)
- **ตัวหนังสือแนวตั้ง**: `rotate(-90deg)` แทน `writing-mode`
- ป้ายในพื้นหลังสี (DOOR / EXIT): `display:inline-block; line-height:1; padding-bottom` มากกว่าด้านบนเล็กน้อย (ฟอนต์ไทยใน html2canvas ลงต่ำ)

## 3. ผังในชีท (`layout.js`)

ฟังก์ชันที่เพิ่มใน `seatPlanLayout()`:
```js
eq(gal, code, type, label)      // ลงทะเบียนอุปกรณ์ Galley (id = gal-code) ชื่อในช่อง = ชื่อสั้น (eqShort) ชื่อเต็มอยู่ใน .full / .name
lav(key, zone, label)           // ลงทะเบียนห้องน้ำ (id = LAV-key)
door(zone, left, right, exit, code)   // แถบประตู A-P เต็มความกว้าง / ทางออกฉุกเฉิน (exit = ป้ายที่คอลัมน์ A และ P เท่านั้น)
gtitle(zone, text, c, span)     // หัว Galley สีฟ้าเทอร์ควอยซ์
blk(zone, label, cells)         // แถว 3 ช่อง: ชื่อ / สภาพ / NOTE  — cell: {id, c, span, rows}
```
- `rows: 2` = ช่องสูงต่อลงไปอีกบล็อก (เช่น Refrigerator, Trolley) — merge NOTE ลงมา
- `{text:'Sink', c, span, fill: SEAT_COLOR.EMPTY}` = ช่องไม่ได้ตรวจ
- คอลัมน์ชีท: A ป้าย EXIT ซ้าย (พื้นขาว นอกลำ กว้าง 60px), B ป้ายแถว, C-H ฝั่งซ้าย (ที่นั่งละ 2 คอลัมน์), I ทางเดิน (แคบ), J-O ฝั่งขวา, P ป้าย EXIT ขวา (พื้นขาว)
- ป้าย EXIT ขึ้นบรรทัดเอง 3 บรรทัด (`◀ EMER\nEXIT\nFWD L`) แถวสูง 46px ให้เห็นครบ · แถบ DOOR ลากจากคอลัมน์ A ถึง P
- ชื่ออุปกรณ์ในช่อง: พื้นเขียว (เหมือน A340) เปลี่ยนเหลือง/แดงตามสภาพด้วย Conditional Formatting
  ขนาดตัวอักษรคำนวณให้คำยาวสุดอยู่บรรทัดเดียว (เช่น Microwave = 6pt) และแถวสภาพสูง 2 บรรทัด
- หัวตารางสรุปขึ้นบรรทัดเองด้วย `\n` (เช่น `Monitor\nเสื่อม\nสภาพ`) เพื่อไม่ให้ Excel ตัดกลางคำ (ห้ามให้สระ/พยัญชนะตัวสุดท้ายตกบรรทัด)

## 4. Excel (`export-excel.js`)
แผ่นงาน "Galley และห้องน้ำ" (แบบ A340): ตารางสรุปตาม Galley + ชนิด, ตารางห้องน้ำตามโซน (สูตร COUNTIFS)
และรายการทุกชิ้นที่ดึงสภาพ/หมายเหตุจากแผ่นงาน "ผังที่นั่ง" ด้วยสูตร

## 5. Apps Script (`apps-script/server.js`)
- `stList_(it)` เลือกรายการสภาพตามชนิด (S / M / E) ใช้ทั้งอ่าน, SAVE, reset, onEdit และ dropdown (`dvE`)
- แท็บ "Galley และห้องน้ำ": รายการ 8 คอลัมน์ (โครงเดียวกับ "ทุกที่นั่ง และ Monitor") + สรุปทางขวา
- "รวมข้อขัดข้องคงค้าง" = FILTER จากทั้งสองแท็บ
- ชื่อซ้ำ (`Stow 1` ของ G1 และ G5) จับคู่ตามลำดับในผัง จึงต้องเรียง `eq()` ใน `layout.js` บนลงล่าง ซ้ายไปขวา

## 6. เช็กลิสต์เมื่อนำไปใช้กับเครื่องลำอื่น
1. ได้ภาพ Galley จากคู่มือ (CCOM-S) ของเครื่องนั้น → กำหนด `GLAYOUT` (cells, bands) และรหัส id
2. กำหนด `LAVS` และตำแหน่งในผัง (`fac`) ให้กว้างเท่าที่นั่งฝั่งนั้น
3. กำหนดประตู/ทางออก (`door`) และ `EQ_CABIN` สำหรับหน้า 3
4. เขียนบล็อกเดียวกันใน `layout.js` (id เดียวกัน, เรียงบนลงล่าง ซ้ายไปขวา)
5. รัน `tools/build-code-gs.sh` → วาง `Code.gs` → `setupSheet` → Deploy New version
6. ทดสอบ: PREVIEW ทั้งสองแบบบนมือถือ/คอม, EXPORT PDF ทั้งสอง, EXPORT TO EXCEL, SAVE แล้วดูในชีท
